# 상권 신호등 — 기술 스펙

기능 목록은 `docs/기능정의서.csv` (Google Sheets 붙여넣기용). 이 문서는 그 기능을 무엇으로 구현하는지만 적는다.

## 1. 아키텍처

```
Next.js 15 (App Router)            Python (FastAPI)
┌──────────────────────┐          ┌─────────────────────┐
│ /market   상권 지도   │  fetch   │ /api/market/*  집계  │
│ /diagnosis 진단 폼    │ ───────► │ /api/diagnosis 추론  │
│ /report   AI 리포트   │  SSE     │ /api/solutions RAG  │
└──────────────────────┘          │ /api/report    LLM  │
        │                          └──────────┬──────────┘
        │ Server Component 직접 조회            │
        ▼                                     ▼
   Postgres (집계 테이블)              risk_model.keras + 벡터 인덱스
```

Python 백엔드를 남기는 이유는 하나뿐이다 — 모델이 Keras고, 파이프라인(`src/`)이 이미 Python이다.
Next.js는 UI와 BFF만 맡는다. 새 서비스는 만들지 않고 비어 있는 `app/` 스캐폴딩을 채운다.

- **읽기 전용 상권 조회(F-MAP-\*)**: Next.js Server Component에서 Postgres 직접 조회. API 홉 불필요.
- **추론·RAG·LLM(F-DIA/RAG/LLM-\*)**: FastAPI 경유. 모델과 인덱스가 Python 쪽에 있다.

## 3. 모델 서빙

입력:
- 시퀀스 `(1, 3, 1)` — 최근 3개월 매출을 **1개월차=100 기준 지수**로 변환. 절대 금액은 모델에 넣지 않는다.
- 정적 피처 — `폐업률_업종내_percentile`, `폐업_률`, `개업_율`, `프랜차이즈_비중`, `KOSIS_산업1` one-hot.
  2025 Q4 기준 `panel_cell`에서 조인(F-DIA-02). 업종 미매핑 시 `전산업` 폴백.

출력 후처리 — **사전확률 보정이 필수다(F-DIA-04)**:

```python
# 학습 위험군 비중 0.30, 실제 서울 약 0.14
p_corrected = p * (prior_real / prior_train)
p_corrected /= p_corrected.sum()
```

생략하면 전 사용자의 위험도가 과대 추정된다. 학습 표본이 의도적 과표집이기 때문이다.

### 무엇을 사용자에게 보여줄 수 있나

| 산출 | 성능 | 서비스 노출 |
|---|---|---|
| 등급 GREEN/YELLOW/RED | 정확도 83.8% (기준선 65.8%), RED 재현율 93.3% | **1차 산출물.** 그대로 노출 |
| YELLOW 등급 | 재현율 33.9% (66%가 GREEN으로 샘) | 노출하되 "확신 낮음" 배지 |
| 6개 원인 유형 | 고금리 92.2% / 단기정체 34.6% / 매출폭락 1.2% / 원가상승·상권침체 **0%** | "추정 원인" + 확률 동반. 확정 진단 금지 |

RED 3유형은 생성기가 같은 궤적(3개월 시점 69.36 / 69.72 / 69.60)에서 뽑았기 때문에 **원리적으로 학습 불가**다. 표본을 33배 늘려도 0%였다. 유형 분류를 제대로 하려면 관측 창을 6~12개월로 늘리고 유형별 궤적을 분리해야 한다 — 이번 범위 밖.

## 4. RAG

현재 TF-IDF를 임베딩으로 교체한다. 인터페이스(`SimpleRAGIndex.retrieve(query, risk_type, top_k)`)는 유지 — 교체가 호출부에 새지 않게 처음부터 그렇게 짜여 있다.

- 임베딩: 한국어 모델(ko-sbert 로컬 또는 상용 임베딩 API). 문서 8건 규모에서는 인메모리 numpy 코사인으로 충분하다. 벡터 DB는 문서가 수백 건을 넘을 때 도입.
- 검색(F-RAG-03): `risk_type_tags` 메타 필터 → 임베딩 코사인 + BM25 결합 → top_k. 필터 결과가 top_k 미만이면 전체 코퍼스 폴백.
- 6개 risk_type 각각에 매칭 문서 최소 1건을 보장해야 한다. 없으면 `solutions[]`가 빈 배열로 나간다.

응답 계약(F-RAG-04):

```json
{
  "risk_level": "RED",
  "risk_type": "고금리_과다채무형",
  "risk_type_confidence": 0.61,
  "score": 32,
  "visual_theme": "red",
  "solutions": [
    { "title": "...", "agency": "...", "summary": "...",
      "limit": "...", "rate": "...", "url": "...", "source_doc_id": "..." }
  ]
}
```

`_similarity_score`는 디버그 전용 — 프로덕션 응답에서 제외.

## 5. LLM

- 모델: `claude-sonnet-5`. 리포트는 SSE 스트리밍(첫 토큰 3초 이내).
- 컨텍스트: 신호 JSON + 검색된 정책 문서 원문**만**. 그 밖의 지식 사용 금지를 프롬프트에 명시.
- 가드레일(F-LLM-02): 생성 후 리포트 내 수치·지원사업명이 입력 컨텍스트에 존재하는지 대조. 불일치 시 1회 재생성, 재실패 시 템플릿 폴백. 금액·금리·신청기간은 환각이 곧 피해다.
- 캐싱(F-SYS-07): `(등급, 유형, 업종, 자치구)` 키는 **사업장 고유값이 없는 부분에만** 건다 — 등급·유형 설명, 지원사업 안내문. 매출지수·score·percentile·행정동 같은 고유 수치는 캐시에 넣지 않고 매 요청 생성해 삽입한다. 같은 키에 서로 다른 사업장이 묶이므로, 캐시 본문에 고유값이 한 번 섞이면 그대로 남의 리포트에 실린다. 저장 직전 고유값 포함 여부를 검사하고, 걸리면 캐싱하지 않는다.

## 6. 반드시 지켜야 할 것

1. **두 결과를 섞지 않는다(F-SYS-01).** `tableau_panel.위험등급`은 실제 통계 기반 *행정동×업종* 결과이고, 모델 `risk_level`은 *개별 가게* 결과다. 용어를 하나로 고정한다 — **"신호등"은 지역 단위(F-MAP)에만**, 사업장 결과는 **"진단 등급"(F-DIA)**. 색 범례와 URL도 분리한다.
2. **사전확률 보정 없이 배포하지 않는다(F-DIA-04).**
3. **정확도를 "예측력"이라 표기하지 않는다(F-LLM-05, F-SYS-08).** 83.8%는 시뮬레이션 규칙 복원율이다. 매출 시계열은 전부 가상이며, 실서비스에서는 카드매출·입출금 데이터로 교체하는 것이 전제다.
4. **점포수 5개 이하 셀에 "표본 적음" 배지.** 가게 3곳이면 폐업률은 0/33/67% 계단값이고, 최댓값 300%는 점포 1개 셀에서 나온다.
5. **매출 실금액 미저장(F-SYS-05).** 정규화 지수만 저장.

## 7. 우선순위

- **P0 (MVP)**: 상권 지도·드릴다운·상세(F-MAP-01~03), 진단 입력→등급 예측→보정(F-DIA-01~04), RAG 색인·검색·응답계약(F-RAG-01~04), 리포트 생성·가드레일·고지(F-LLM-01/02/05), 데이터 적재·두 신호등 분리·접근성·개인정보·한계고지(F-SYS-01/03/04/05/08)
- **P1**: 추이·랭킹·필터, 6유형 분류, 위험점수, 상권 대비 위치, 후속 QA, 성능·모니터링·비용
- **P2**: 진단 이력 공유, 지표 자연어 해설, 문서 자동 수집
